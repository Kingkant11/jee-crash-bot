# JEE Crash Bot - Requirements Document

## 1. Product Overview

**JEE Crash Bot** is an AI-powered Telegram bot designed to help JEE Main aspirants prepare for Session 2 through personalized diagnostic testing, weakness analysis, and targeted study plans.

### 1.1 Product Vision
Transform JEE Main Session 2 preparation by providing AI-driven diagnostics that identify exact weaknesses and create personalized 7-day crash plans to maximize scores.

### 1.2 Target Users
- JEE Main 2025/2026 aspirants
- Students who appeared in Session 1 and need focused Session 2 preparation
- Students preparing for first-time JEE Main attempt
- Age: 16-19 years
- Comfortable with Telegram messaging

### 1.3 Key Value Proposition
- **AI-Powered Diagnostics**: 10-question diagnostic test identifies exact weaknesses in 10 minutes
- **Personalized Analysis**: Multi-agent AI system (Researcher, Analyst, Planner) provides tailored insights
- **Targeted Study Plans**: 7-day crash plan with 210 questions focused on weak areas
- **Session 2 Focus**: Content optimized for Session 2 trends and high-weightage topics
- **Affordable**: Premium features at ₹99

## 2. Functional Requirements

### 2.1 User Management

#### FR-1: User Registration
- **Priority**: High
- **Description**: System must register new users when they start the bot
- **Requirements**:
  - Capture Telegram ID, username, first name, last name
  - Generate unique referral code
  - Store user metadata (created_at, last_active)
  - Handle existing users gracefully
- **Acceptance Criteria**:
  - User receives welcome message on /start
  - User account created in database
  - Unique referral code generated

#### FR-2: User Profile
- **Priority**: Medium
- **Description**: Maintain user profile with statistics
- **Requirements**:
  - Track total tests taken
  - Track highest score
  - Track payment status
  - Track referral code and referrals
- **Acceptance Criteria**:
  - User can view stats via /stats command
  - Profile updates after each test

#### FR-3: Referral System
- **Priority**: Low (Planned Feature)
- **Description**: Users can refer others for benefits
- **Requirements**:
  - Generate unique referral code per user
  - Track referrals made by user
  - Provide benefits for successful referrals
  - Handle referral links in /start command
- **Acceptance Criteria**:
  - Referral code displayed in profile
  - Referrer gets benefits when new user signs up

### 2.2 Diagnostic Testing

#### FR-4: Test Generation
- **Priority**: High
- **Description**: Generate 10-question diagnostic test
- **Requirements**:
  - 4 Physics, 3 Math, 3 Chemistry questions
  - Focus on high-weightage topics (Mechanics, Calculus, Organic Chemistry)
  - Mix difficulty: 3 easy, 4 medium, 3 hard
  - Questions generated by AI (Groq Llama 3.3 70B)
  - Questions saved to database
- **Acceptance Criteria**:
  - Test generated within 15-20 seconds
  - Questions valid JSON format
  - All required fields present (question, options, answer, subject, chapter, topic, difficulty, explanation)

#### FR-5: Test Taking
- **Priority**: High
- **Description**: Interactive test-taking experience
- **Requirements**:
  - Send questions one-by-one
  - Inline keyboard for answer selection
  - Track time taken
  - Prevent multiple active tests per user
  - Allow test cancellation
- **Acceptance Criteria**:
  - User can answer via button clicks
  - Progress shown (Question X/10)
  - Test completes after all 10 questions
  - /cancel command works mid-test

#### FR-6: Result Calculation
- **Priority**: High
- **Description**: Calculate and display test results
- **Requirements**:
  - Calculate correct/incorrect answers
  - Calculate percentage score
  - Track time taken
  - Save results to database
  - Update progress tracking
- **Acceptance Criteria**:
  - Score accurately calculated
  - Results saved to database
  - Progress updated correctly

### 2.3 AI Analysis

#### FR-7: Performance Analysis
- **Priority**: High
- **Description**: Analyze test results to identify weaknesses
- **Requirements**:
  - Calculate subject-wise scores
  - Identify 3 weakest chapters (accuracy < 60%)
  - Detect error patterns (conceptual, calculation, silly mistakes)
  - Provide actionable recommendations
  - Estimate Session 2 marks impact
- **Acceptance Criteria**:
  - Analysis generated within 10 seconds
  - Weak chapters accurately identified
  - Error patterns detected
  - Recommendations provided

#### FR-8: Progress Tracking
- **Priority**: Medium
- **Description**: Track user progress over multiple tests
- **Requirements**:
  - Track subject-wise performance
  - Track chapter-wise accuracy
  - Track improvement over time
  - Provide progress reports
- **Acceptance Criteria**:
  - Progress viewable via /progress command
  - Historical data maintained
  - Trends visible

### 2.4 Study Planning

#### FR-9: Personalized Plan Generation
- **Priority**: High
- **Description**: Generate 7-day personalized study plan
- **Requirements**:
  - Focus on weakest chapters (Days 1-3)
  - 30 targeted questions per day (210 total)
  - Subject-wise distribution
  - Topic focus with difficulty progression
  - Include PYQs (Previous Year Questions)
  - Mermaid diagrams for key concepts
  - Key formulas for each day
  - Session 2 percentile predictor (Day 7)
- **Acceptance Criteria**:
  - Plan generated within 20-30 seconds
  - 7 days of content provided
  - Content personalized to weaknesses
  - All required fields present

#### FR-10: Plan Delivery
- **Priority**: High
- **Description**: Display study plan to user
- **Requirements**:
  - Format plan for Telegram display
  - Split long messages (Telegram 4096 char limit)
  - Use MarkdownV2 formatting
  - Include visual elements (emojis, formatting)
- **Acceptance Criteria**:
  - Plan displayed in readable format
  - All content visible
  - No formatting errors

### 2.5 Payment & Premium Features

#### FR-11: Payment Simulation
- **Priority**: High (Current) / Medium (Future)
- **Description**: Handle payment for premium features
- **Requirements**:
  - Display payment information (/pay99)
  - Simulate payment for testing (/paid)
  - Mark user as paid in database
  - Unlock premium features after payment
  - Future: Integrate Razorpay payment gateway
- **Acceptance Criteria**:
  - Payment info displayed clearly
  - Payment simulation works
  - Premium features unlocked after payment

#### FR-12: Premium Access
- **Priority**: High
- **Description**: Provide premium features to paid users
- **Requirements**:
  - Access to personalized study plan
  - Detailed performance analysis
  - Advanced progress tracking
  - Priority support (future)
- **Acceptance Criteria**:
  - Paid users can access /myplan
  - Plan generated and displayed
  - Premium features work correctly

### 2.6 Bot Commands

#### FR-13: Command Set
- **Priority**: High
- **Description**: Provide comprehensive command set
- **Requirements**:
  - /start - Initialize bot and show welcome
  - /test - Start diagnostic test
  - /history - View test history
  - /progress - Check subject-wise progress
  - /stats - View user statistics
  - /myplan - View study plan (premium)
  - /pay99 - Show payment info
  - /paid - Simulate payment (testing)
  - /cancel - Cancel active test
  - /help - Show help message
- **Acceptance Criteria**:
  - All commands work correctly
  - Help messages are clear
  - Error handling in place

### 2.7 Data Persistence

#### FR-14: Database Management
- **Priority**: High
- **Description**: Maintain data persistence
- **Requirements**:
  - SQLite database for storage
  - Tables: users, tests, progress, question_bank
  - Backup and recovery mechanism
  - Data integrity constraints
- **Acceptance Criteria**:
  - Data persists across bot restarts
  - No data loss
  - Proper indexing for performance

### 2.8 Health & Monitoring

#### FR-15: Health Checks
- **Priority**: Medium
- **Description**: Monitor bot health
- **Requirements**:
  - HTTP server for health checks
  - /health endpoint returns status
  - Uptime tracking
  - Error logging
- **Acceptance Criteria**:
  - Health check returns 200 OK
  - Uptime tracked correctly
  - Errors logged appropriately

## 4. Technical Architecture

### 4.1 System Components

#### 4.1.1 Telegram Bot Interface
- **Technology**: node-telegram-bot-api
- **Purpose**: Handle Telegram messages and commands
- **Commands**: /start, /test, /history, /progress, /stats, /myplan, /pay99, /paid, /cancel, /help

#### 4.1.2 Multi-Agent AI System
- **Researcher Agent**: Generates JEE questions
  - API: Groq Llama 3.3 70B
  - Function: researcherAgentGenerateQuestions()
  
- **Analyst Agent**: Analyzes test results
  - API: Groq Llama 3.3 70B
  - Function: analystAgentAnalyze()
  
- **Planner Agent**: Creates study plans
  - API: Groq Llama 3.3 70B
  - Function: plannerAgentGeneratePlan()

#### 4.1.3 Database Layer
- **Technology**: SQLite3
- **Tables**: users, tests, progress, question_bank
- **Features**: Indexes, constraints, JSON storage

#### 4.1.4 HTTP Server
- **Technology**: Express.js
- **Purpose**: Health checks and uptime monitoring
- **Endpoints**: /, /health

### 4.2 Data Flow

```
User → Telegram → Bot.js → AI Agents → Groq API
                            ↓
                         Database
                            ↓
                         User Response
```

### 4.3 External Dependencies
- **Groq API**: AI model for question generation, analysis, planning
- **Telegram Bot API**: Bot messaging
- **Razorpay**: Payment processing (future)

## 5. Constraints & Assumptions

### 5.1 Constraints
- **Telegram Limits**: 4096 characters per message, 20 messages per minute to groups
- **Groq API**: Rate limits, token costs
- **Payment**: Currently simulated, real integration needed
- **Single Bot Instance**: No multi-instance support yet

### 5.2 Assumptions
- Users have Telegram installed
- Users have basic JEE knowledge
- Session 2 trends similar to Session 1
- AI models provide accurate JEE content
- Payment gateway integration feasible

## 8. Risk Assessment

### 8.1 Technical Risks

### 8.2 Business Risks

- **Payment Issues**: Mitigation - Multiple payment options, support
